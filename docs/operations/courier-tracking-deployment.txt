No shared service was restarted, recreated, migrated or repaired during this work.
The root Compose file keeps S3 Flyway disabled, validation enabled, proof/outbox
workers disabled, and restart=no. The separate approval-required override is NOT
loaded by a normal docker compose command.

Application read flow after deploying code:
  Courier JWT -> gateway REST -> S3 canonical assignment ownership/ACCEPTED check
  -> authenticated S2 gRPC -> S2 parcel + immutable status history + outbox commit.
  S4 GraphQL and REST public tracking read the same real S2 parcel/history by
  reference. Owner-only GraphQL first verifies ownership via S2 and resolves the
  assigned courier via S3 gRPC for that exact parcel ID. Public APIs omit names,
  phones, private notes, actor subjects and full addresses.
  No status is inferred from another shipment or invented as an event.
  Accepted assignment changes assignment state; it does not imply PICKED_UP.

Event and completion flow (requires separately approved worker configuration):
  S2 publisher -> Kafka parcel.created / parcel.status.updated -> S4 transactional
  processed_event claim + tracking history/projection -> after-commit SSE.
  S3 proof submission saves immutable evidence as PENDING; the proof worker calls
  S2 CompleteParcelDelivery via service-authenticated gRPC and confirms COMPLETED.
  Same-state status retries produce no new history/outbox entry. Proof retries
  preserve identical evidence. Kafka consumers deduplicate original event IDs.
  S3 outbox remains OFF in the proposed deployment: owner courier details use
  its authoritative read API and do not require publishing assignment events.

No live data-repair SQL is proposed. The source S2 history already exists and
is sufficient for read aggregation; approved publication can populate S4 later.
Old S3 assignment-event projection concerns are not a reason to enable its outbox:
those events carry profile IDs, while tracking authorization expects subjects.
Keep that outbox disabled as specified; courier details are read from S3 gRPC.
